== まとめ

本書では，BOTS v1 ~ v3 の 98 問の解き方を解説した．
最後に，全問題を通じて繰り返し出てきた調査の考え方を振り返る．

=== 調査の進め方

. **データの棚卸しから始める．** `tstats` で `sourcetype` の一覧を作り，どのログで何が分かるかを把握する．
. **手がかりの文字列でキーワード検索し，ヒットした `sourcetype` を見る．** ドメイン名，ファイル名，IP アドレスは，複数のデータソースをつなぐ鍵になる．
. **ネットワークと端末を行き来する．** HTTP や DNS で見つけた通信を，Sysmon や osquery のプロセス・ファイルの記録と突き合わせると，何が起きたかが確定する．
. **時刻で並べて流れを読む．** `sort 0 _time` で時系列に並べると，偵察 → 侵入 → 実行 → 持ち出しという攻撃の段階が見えてくる．
. **答えは別の証拠で裏を取る．** 1 つのログだけで判断せず，別の `sourcetype` でも同じ事実が確認できるかを確かめる．

=== 問題文を正確に読む

正解にたどり着けなかったケースの多くは，ログの読み違いではなく問題文の読み違いだった．

* 「unique（種類数）」なのか「回数」なのか（305，1507）
* 「公開（public）」アドレスなのか，内部アドレスなのか（1201）
* 「index time」なのか，ファイルに記録された時刻なのか（1304，1305）
* 「from this activity」のような限定（2109）
* 「first seen」と Splunk の `first`/`last` の関係（2111）
* 答えの書式（FQDN かドメインか，空白の有無，アルファベット順）

=== Splunk の外の知識

いくつかの問題は，ログだけでは答えが決まらず，外部の知識を組み合わせる必要があった．

* OSINT（passive DNS）でドメインを調べる（202）
* USB のベンダー ID からメーカーを調べる（1308）
* AMI の ID から OS を調べる（2400）
* エクスプロイトや攻撃手法から CVE を特定する（2402，2403）
* 手法の名前を知っている（414 のステガノグラフィ）

実際のインシデント対応でも，ログで得た手がかりを脅威インテリジェンスや公開情報と組み合わせることは欠かせない．

* https://github.com/splunk/botsv1[BOTS v1]，https://github.com/splunk/botsv2[BOTS v2]，https://github.com/splunk/botsv3[BOTS v3] のデータセットは GitHub で公開されている．自分の Splunk に取り込んで復習できる．
* https://docs.splunk.com/Documentation/Splunk/latest/SearchReference/[Splunk Search Reference] で，本書で使ったコマンド（`stats`，`rex`，`spath`，`eventstats` など）の詳細を確認できる．
* 元の BOTS には，本書の演習環境に含まれていない問題（Splunk Enterprise Security を使うものなど）もある．
